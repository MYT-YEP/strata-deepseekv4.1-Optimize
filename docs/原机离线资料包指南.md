# Strata + DeepSeek V4.1 Flash + Harness 复现全流程

适用对象：Windows 用户，以及在另一台电脑上代为执行的 AI。本文记录本机 **2026-10-29 已选定并设为默认** 的方案；它不是通用的“最新版本”安装教程。

## 0. 先看结论和边界

目标是复现：`DeepSeek V4.1 Flash 1017` 的 **ISTA-DASLab 2.25 bpw / IQ2_XS** 模型，加上 Strata 原版回退、Xolotl 快速引擎、DSpark 草稿模型和 DeepSeek Harness。全部路径固定在 `F:\STRATA`。

本机已测：快速版 64K 上下文、16K 单次输出；六题预热后加权纯生成 **22.196 token/秒**，单题 **15.2–29.4 token/秒**，包含等待的完整请求平均 **17.659 token/秒**。此前冷启动六题加权纯生成 **14.902 token/秒**；历史最好一次六题加权纯生成 **27.633 token/秒**。这些不是其他机器的速度保证，也没有证明稳定达到 20 token/秒。回答、系统负载、缓存和采样会改变结果，不能把不同次运行的差异直接归因于预热。

**快速版只支持文本，专家路由偏置会改变回答并可能降低质量。** 原版服务声明支持图片输入，但本轮未实际验证图片推理。65,536 token 是输入、系统提示和输出共享的上下文预算；16,384 是单次输出上限，触及上限会截断。

本资料包已复制并逐文件核对运行时、配置和源码；两份补丁已在各自干净基线上实际应用并与本机源码比较。模型文件的期望 SHA-256 来自固定版本安装器和已有 `.done` 记录，**生成资料包时没有重新读取约 275 GB 权重计算哈希**。资料包尚未在第二台电脑完成端到端启动，必须由目标机实际验证，不能宣称“其他机器已经复现成功”。

**启动器版本差异：**资料包保存的是此前实测时使用的 `harness-fast-launch.cjs`，其 `TEMP`、`TMP` 均指向 `F:\STRATA\tmp`。打包期间，原机该文件被另一工作流改为指向 C 盘用户临时目录；原机现存文件未被本次操作覆盖。除此项差异和预设的 `last_used` 时间戳之外，资料包快照按清单逐文件核对。原机后续修改的原因及对其他环境的影响不在本次验证范围内。

## 1. 给执行 AI 的任务约束

1. 只复现本文指定的已选方案；不要自动测试或切换其他模型、量化版本和调参方案，不要自动配置 Codex 辅助代理入口。
2. 先检查目标电脑、盘符、空闲空间、GPU/驱动和端口；已有文件、现有服务、用户数据和会话都要保留。不要删除或覆盖不属于本次安装的文件，也不要并发启动同一模型。
3. 所有程序、模型、缓存和新测试记录放在 `F:\STRATA`。本方案脚本中有大量该绝对路径，**其他盘符不能只改一处就认为可用**。
4. 精确使用本包内配置、排序文件、源码和指定模型文件；不要用最新分支、最新 npm 版本或其他量化档替代。长下载中断时保留文件并使用原下载器的续传功能。
5. 安装后检查真实 `/health`、`/v1/models`、一次实际推理、Harness 文件工具及输出限制；记录实际答案、耗时、token 和可获得的速度。没有测到的项目必须标明未测。
6. 停止快速版后确认原版模型恢复。不要将“文件已复制”“健康接口成功”当作真实推理成功，也不要把一次峰值当作稳定速度。

## 5. 推荐路线：使用本机生成的复现资料包

资料包目录：`F:\STRATA\复现资料包-20261029`。运行时快照含 81,265 个文件，约 2.86 GB（十进制）；它还包含已编译引擎、两份源码补丁、两套 Harness profile、启动/恢复脚本、模型映射及 tokenizer、专家排序文件、校验清单和安装/核验脚本；**不包含上表模型文件、聊天会话、网页认证文件、工作区文件或运行中进程记录**。复制前仍应自行检查是否适合分享。

### 5.1 目标机准备

1. 确认是 Windows x64、NVIDIA GPU、驱动和 Microsoft Visual C++ x64 运行库可用；同原机 GPU/CPU 更有可能运行包内二进制。准备 `F:` 盘及足够空间。
2. 确认 8080、8150、3080、3081 本机端口没有被不相关程序占用；不能为复现随意终止其他程序。
3. 将整个 `复现资料包-20261029` 复制到目标机或外置盘。例如下例假设它位于 `E:\复现资料包-20261029`；按实际路径修改 `$bundle`。另准备模型文件的两个目录。
4. 如果 `F:\STRATA` 已有内容，安装器先比较每个同名文件；不同内容会报冲突并停止，不会自动覆盖。应先审查或备份，而不是删除已有目录。

可在 PowerShell 先收集机器信息和监听端口（输出为空通常表示该端口没有监听者；命令失败时不能当作通过）：

```powershell

Get-CimInstance Win32_ComputerSystem | Select-Object TotalPhysicalMemory

```

### 5.3 提供模型

推荐把原机两个模型目录复制到目标机的 `F:\STRATA\data\models`，保留文件名、层级和同名 `.done` 文件。复制大文件建议用支持断点续传的工具；不要使用会删除目标多余文件的镜像选项。若目标已有同名文件，先核对归属及哈希，不要自动覆盖。`.done` 是历史完成记录，不能替代目标机的实际哈希检查。

如没有原机权重，可从第 4 节指定的两个固定 revision 下载。原机使用的镜像前缀是 `https://hf-mirror.com`：前四个主模型分片及 Engram 的 URL 形式为 `https://hf-mirror.com/ISTA-DASLab/DeepSeek-V4.1-Flash-1017-GSQ-RCO-GGUF/resolve/cb02422c900df489cea5833e8a92171224059b3c/<文件名>`；DSpark 和 mmproj 为 `https://hf-mirror.com/unsloth/DeepSeek-V4.1-Flash-1017-GGUF/resolve/f924b94f19c1fea02c06a65c8475b0a45e2b88b1/<文件名>`；小元数据文件同样使用 Unsloth 地址，但在文件名前加 `UD-Q8_K_XL/`。文件名、大小、哈希和落盘目录均按第 4 节及 `manifest.json`，不得改用最新 revision。

下载到单独的临时文件，实际大小和 SHA-256 都正确后再移动为正式文件。支持 HTTP Range 的下载器可以断点续传；若镜像不支持续传或校验失败，保留临时文件和日志并停止，不要覆盖或删除已有文件。用同一个下载器、同一个固定 URL 续传；不要混用别的下载器生成的 `.part` 或分片状态。示例：下面只下载第一个主模型分片，其他七个文件按前述 URL 映射及清单重复操作：

```powershell
$folder = 'F:\STRATA\data\models\deepseek-v4.1-flash-IST-DAS-2.25bpw'
$name = 'DeepSeek-V4.1-Flash-1017-GSQ-RCO-IQ2_XS-00001-of-00004.gguf'
$dest = Join-Path $folder $name
$part = "$dest.repro-part"
$size = 39535776992
$sha = '4c65307992ab586c527ca1f6f64062aa96a33b23c02b7fed103f45f75e854798'
$url = 'https://hf-mirror.com/ISTA-DASLab/DeepSeek-V4.1-Flash-1017-GSQ-RCO-GGUF/resolve/cb02422c900df489cea5833e8a92171224059b3c/' + $name
if (Test-Path -LiteralPath $dest) { throw '正式文件已存在；保留并先核对。' }
New-Item -ItemType Directory -Path $folder -Force | Out-Null
if ((Test-Path -LiteralPath $part) -and (Get-Item -LiteralPath $part).Length -gt $size) { throw '临时文件超出预期；保留并检查。' }
if (-not (Test-Path -LiteralPath $part) -or (Get-Item -LiteralPath $part).Length -lt $size) {
  & curl.exe --location --fail --retry 5 --continue-at - --noproxy '*' --output $part $url
  if ($LASTEXITCODE -ne 0) { throw '下载中断；保留临时文件，排查后可用同一命令续传。' }
}
if ((Get-Item -LiteralPath $part).Length -ne $size -or (Get-FileHash -LiteralPath $part -Algorithm SHA256).Hash.ToLowerInvariant() -ne $sha) { throw '临时文件校验失败；已保留。' }
[IO.File]::Move($part, $dest) # 目标已存在时不覆盖
```

示例中的 `curl` 新建与续传参数只用本地小文件做过检查，未在第二台电脑对镜像做大文件下载测试；镜像是否可用和 Range 行为须在目标机确认。如果固定 revision 不可获取，应从原机复制。不要把 `start-deepseek-for-harness.cmd` 当成可靠的下载器：随包已有安装配置和 pack，启动器可能将其视为已安装；它还带有 `--restart`。原版 `setup.py` 可能在校验失败时删除损坏的下载文件或重建 pack，运行前应先了解这些行为。

在首次启动之前执行；第二条会重新读取约 275 GB，可能耗时较长：

### 5.5 启动和回退

双击 `F:\STRATA\start-harness.cmd`，或在 PowerShell 中执行 `& 'F:\STRATA\start-harness.cmd'`。首次加载可能约一分钟，脚本会自动打开带本机认证信息的网页；不要把认证链接或 `.credentials.yaml` 发给他人。

**排序文件必须按本包复制。** 当初 `convert-profile.py` 从旧版 `expert-profile.bin` 生成排序；原统计文件后来已变化，因此现在重新执行转换不一定得到同一排序。排序文件是 122,880 字节，本包已保存并校验。

Xolotl 的本地补丁将 Unsloth DSpark/DFlash 的张量名称映射到引擎期望名称，复用同一草稿权重；不是重写主模型。快速启动时引擎日志应出现 `DSpark: using 78 audited dflash tensor aliases`。ggml 的 20 文件补丁也是此二进制构建所需，不要只打 DSpark 补丁。

## 8. 源码重建路线：版本不变，二进制未必逐字节相同

优先使用包内与目标硬件兼容的现成程序。源代码重建适用于原二进制因 GPU 架构或 CPU 指令集不匹配而无法运行的情况；重建需要 Visual Studio C++ 构建工具、CMake、Ninja 和匹配的 CUDA Toolkit。包内提供了已打补丁的完整 Xolotl/llama.cpp 源码快照以及 `evidence\configure-xolotl.cmd` 的原机配置。两份补丁可用于独立从 Git 还原：

## 10. 常见阻碍与原始资料

- `F:` 不存在、空间不足或 GPU 架构不匹配：先解决环境问题，不能改变路径或缓存后仍称完全相同。
- 端口占用或已有用户任务：保留现有进程，等空闲或由使用者明确处理。
- 校验不符：停止启动，保留文件及下载记录；不要把 `.done` 当作实际内容哈希。
- 缺少 CUDA / VC++ DLL：核对驱动、运行库及 JSON 中 `lib_dirs`。不同机器重建需要自己的工具链；包内 CMakeCache 的绝对路径是历史证据，不应直接复用。
- 会话和凭据不在包内：新机器将生成自己的本机认证信息，旧会话如需迁移必须由用户另行处理。
- 详细报告：`evidence\原机运行测试报告.md`；最近一轮冷、热六题结果及采样、Harness 和恢复检查的原始记录副本：`evidence\historical-tests\`。报告内仍保留原机路径，迁移后应到此副本目录查找对应文件；资料包不包含所有历史实验日志。逐文件校验：`manifest.json`；源代码补丁：`patches\`。
